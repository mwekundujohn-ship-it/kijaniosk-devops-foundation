# Fault Injection Log

Each fault was injected on the `feature/week5-ci-pipeline` branch, one at a time, against the committed pipeline. After every fault the change was reverted to commit `15807c2` and the pipeline was run again until it returned to green. The fault commits were never pushed; their identifiers are recorded below so each entry can be matched to the build log that produced it.

| # | Step faulted | How the fault was injected | Observed downstream behaviour | Why this is the correct design |
|---|---|---|---|---|
| 1 | Lint | Appended a 143-character comment line to `week5/friday/app/src/payments.js` (fault commit `34b5a14`). | Lint failed with `payments.js:52: line longer than 120 characters`. Build, Verify, Test, Security Audit, Archive and Publish were skipped. Reverted to `15807c2`; the next run was green. | Lint runs before Build so a formatting defect stops the run before any time is spent building or testing code that cannot be read. |
| 2 | Build | Inserted `throw new Error(1);` into `week5/friday/app/scripts/build.js` (fault commit `bc842e5`). | Lint passed. Build failed with `Error: 1`. Verify, Test, Security Audit, Archive and Publish were skipped. Reverted to `15807c2`; the next run was green. | A package that cannot be assembled has nothing to test, fingerprint or publish, so the remaining work would be wasted. |
| 3 | Verify (Test) | Changed one expected total in `week5/friday/app/test/payments.test.js` from 42 to 43 (fault commit `22836fa`). | Lint and Build passed. Test failed with `calculateTotal applies quantity to each line: Expected values to be strictly equal`. Security Audit ran in parallel and passed with `found 0 vulnerabilities`. Archive and Publish were skipped. Reverted to `15807c2`; the next run was green. | Wrong payment behaviour must never be published, and the parallel audit still finishes so its result is not lost. |
| 4 | Archive | Added a non-existent file, `missing-artifact.txt`, to the tar command in the Jenkinsfile (fault commit `8002413`). | Lint, Build, Test and Security Audit passed. Archive failed with `tar: missing-artifact.txt: Cannot stat: No such file or directory`. Publish was skipped. Reverted to `15807c2`; the next run was green. | Without a complete, fingerprinted package there is nothing trustworthy to publish, so publication is correctly blocked. |
| 5 | Publish | Pointed the registry URL at `127.0.0.1:9999` instead of the Nexus port (fault commit `7483fed`). | Lint, Build, Test, Security Audit and Archive passed. Publish failed with `ECONNREFUSED` while contacting the registry, so no package was uploaded. Reverted to `15807c2`; the next run was green. | A failed upload must not be reported as a release; the earlier checks remain valid and the last good version stays available. |

All five faults were reverted with `git reset --hard 15807c2`, and a fresh build confirmed green before the next fault was injected.

## Pipeline version note

The faults above were injected against the pipeline as committed at `15807c2`. The only Jenkinsfile changes made afterwards affected the Publish stage's credential handling (removing a masked credential echo and adding an `EXIT` trap so `.npmrc` is always deleted) and the wording of the `post` messages. Neither change alters the stage order, the parallel Verify branches, or which stages are skipped when a stage fails, so the observed behaviour in the table still describes the committed pipeline. The final committed Jenkinsfile is `ee20e05`; the final green run against it is build #19 (`green-pipeline-run.txt`), and the credential audit was re-run against `ee20e05` (`credential-audit.txt`).
