# Environment setup and tool stack

This documents the exact tools used to build and run the Week 4 pipeline, so the
result can be reproduced.

## Path used: **cloud**

The brief's primary path is Multipass + MinIO. Neither is usable on this
controller, so the **optional cloud path** was used (the brief states all five
Requirement 1 criteria are assessed identically on either path):

- **No Multipass:** it ships only as a snap on Linux; this controller (Kali) has
  no snapd, and Multipass is not in the distro repositories.
- **No MinIO:** the open-source MinIO server has been archived and is no longer
  distributed (the download endpoint returns HTTP 410 and the Docker image is no
  longer pullable). A replacement local S3-compatible server was not installed.

Consequently:

| Layer | Primary path (brief) | This submission (cloud path) |
|-------|----------------------|------------------------------|
| Compute | Multipass VMs | AWS EC2 instances (Ubuntu 22.04) |
| Remote state | MinIO bucket (no native locking) | AWS S3 bucket + **S3-native lock file** (locking enabled) |
| IP discovery | `multipass info` | `terraform output -raw <role>_server_ip` |
| SSH key | `~/.ssh/id_rsa` | `~/.ssh/kijaniosk_ed25519` (variable `key_name = "kijaniosk"`) |

`pipeline.sh` still accepts a `multipass` argument and contains the
`multipass info` code path, so the pipeline can be pointed at the primary path on
a machine that has Multipass. It defaults to `cloud`.

## Setup steps

```bash
# 1. Controller tools
pipx install ansible
#    terraform and aws-cli were installed previously

# 2. Backend + SSH key (creates S3 bucket, lock setup and the EC2 key pair)
export AWS_REGION=us-east-1
./scripts/bootstrap-backend.sh
#    -> note the printed admin CIDR and put it in terraform/terraform.tfvars

# 3. Terraform
cd terraform
terraform init
terraform apply          # provisions 3 servers

# 4. Full pipeline (Terraform -> inventory -> Ansible)
cd ..
./pipeline.sh cloud

# 5. Teardown
cd terraform && terraform destroy
```

`terraform/terraform.tfvars` holds the environment-specific values
(`aws_region`, `instance_type`, `key_name`, `admin_cidr`, `ssh_key_path`); no
such value is hardcoded in a resource block.

## Reproducibility notes

- The AMI is resolved at plan time from Canonical's public Ubuntu 22.04 image
  (data source, no hardcoded AMI id).
- The inventory is regenerated by `pipeline.sh` from live Terraform outputs on
  every run; it is never edited by hand.
- The S3 state bucket has versioning and default encryption enabled.
- `pipeline.sh` was run twice; both runs are captured in `pipeline-run1.log`
  (18 changes per host) and `pipeline-run2.log` (0 Terraform changes,
  `changed=0` on all hosts).
